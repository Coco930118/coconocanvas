01 · バッチスケジュール仕様

バッチ生成は「期間指定」で動く。 期間を渡すと、内部で決まった時間帯に投稿枠を自動展開する。 1日5枠、最大30枠まで。

標準時刻テンプレート

プラットフォーム 時刻 狙い
X 06:00 通勤前。冷静な朝の頭に刺さる一撃
Threads 07:00 起き抜け。まだ言語化されていない感覚に寄り添う
Threads 10:00 午前の隙間。ちょっとした共感を置いておく
Threads 19:00 夕方の疲れどき。静かに届く言葉
X 22:00 夜。組織の問題を一人で抱えている人の画面に滑り込む
1日5枠 × 6日 = 30枠が上限。超えた場合は自動トリム（末尾を切る）してから警告を出す。

サンプル：4月13日 06:00 〜 4月15日 22:00（15枠）

3日間 × 5枠 = ちょうど15枠。 バッチパーサーは開始・終了時刻を含む形で枠を展開する。

期間入力フォーマット（受け付けるすべての形式）

形式例
日本語 4月13日 06:00 〜 4月15日 22:00
スラッシュ 2026/4/13 6:00 〜 2026/4/15 22:00
ISO（ハイフン） 2026-04-13 06:00 〜 2026-04-15 22:00
矢印セパレータ 4/13 6:00 → 4/15 22:00
から〜まで 4月13日6時から4月15日22時まで
パーサー注意点： ISO形式の日付ハイフン（2026-04-13）は日付区切りとして扱う。 セパレータとして機能するのは「スペース + ハイフン + スペース」形式（ - ）のみ。 それ以外のハイフンは絶対に変換しない。

警告ケース一覧

プレフィックス条件UI挙動
OVER_LIMIT: 30枠超 末尾トリム後に警告表示、確定ボタンで続行
PAST_DATE: 開始が過去日時 「このまま生成」ボタン＋キャンセルを表示
YEAR_CROSS: 年をまたぐ 年表示付きで確認バナーを出す

エラーケース（パース失敗）

  • 空白：入力が空のまま確定 → 「期間を入力してください」
  • 不明瞭：日時が読み取れない → 「日時の読み取りに失敗しました」
  • 終了 < 開始：終了が開始より前 → 「終了日時が開始より前です」

02 · キャラクター定義 / 強弱スペクトラム

このアプリが出す言葉の源泉。AIが自然に作りやすい「整った正論」や「前向きなまとめ」を 意図的に避けて、40年以上生きてきた人間の枯れた現場感を再現する装置として設計してある。

キャラクターの本質

項目内容
背景 40年以上の人生経験。ネイル・飲食・BAR運営など20年の現場歴
避けること 前向きな正論、応援、綺麗なまとめ。「いいことを書こう」としない
大切にすること 自嘲・泥臭さ・余白・ズレた本音。自分の中で自然に出た言葉だけを選ぶ

強弱スペクトラム v4.2

毎回の生成で coldness（冷徹度）と rawness（泥臭さ度）を 0〜10 で設定する。 両方を均等に入れるのではなく、その日の呼吸を優先する。

パラメータ0 寄り10 寄り導出
coldness 温かみ・揺らぎがある 冷徹・切り捨て・論理的 X：スライダー 10 - tone / Threads・Batch：サーバー乱数
rawness 整った言葉・静かな観察 泥臭さ・生々しさ・現場感 X：スライダー tone / Threads・Batch：サーバー乱数
X タブのスライダーは「冷徹寄り ←→ 泥臭さ寄り」の1本。 スライダー操作前はサーバー側ランダム（isManual: false）。 動かした瞬間から手動モードに切り替わり、リセットボタンで戻る。

言葉の息づかいルール v4.2追加

v4.2 で追加した制約。整いすぎた文章を防ぐための仕組み。 システムプロンプトに毎回注入する。

  • 「なんとなく」「少し複雑」「少し不思議」などの感触語を同一投稿内で繰り返さない
  • 説明を足したい衝動を手放す。余白に意味がある
  • 整った文章より、途中で少し崩れている呼吸感を大切にする
  • 独り言のように書いて、誰かに届いたらそれでいい、くらいの温度感で

前回パターン注入

生成のたびに直前の名言／お守り言葉の構文パターンを previousPattern として渡す。 同じ構文の繰り返しを避けるための仕組み。 localStorage に保存して引き継ぐ。 

// localStorage キー
quiet-tuning-previous-pattern

// システムプロンプトへの注入（毎回）
前回名言・お守り言葉の構文パターン：${previousPattern || '（初回・記録なし）'}
※同じ構文パターンを繰り返さないこと。

パースロジック

// lib/parseResponse.ts
function parseXResponse(raw: string): ParsedX | ParseError {
  const thinking = extract(raw, 'THINKING');
  const body     = extract(raw, 'BODY');
  const meigen   = extract(raw, 'MEIGEN');
  if (!body || !meigen) return { success: false, raw };
  return { success: true, thinking, body, meigen };
}

// セクション抽出（共通ユーティリティ）
const re = new RegExp(`===${name}===([\\s\\S]*?)(?:===[A-Z]+===|$)`);
return raw.match(re)?.[1].trim() ?? '';

Threads 向け。Role は「夜の静かな共犯者」— 人間関係に静かな疲れを抱えた大人に、押しつけずそっと寄り添う言葉を置く。

05 · API / SSE仕様

生成リクエストは POST /api/generate の1本。 通常はSSEストリームで進捗を流す。バッチモードだけプレーンなJSONで返す。

リクエスト型（GenerateRequest）

interface GenerateRequest {
  platform?:       'x' | 'threads';  // デフォルト 'x'
  hint?:           string;            // ユーザー任意入力
  usedQueries?:    string[];          // 使用済みクエリ（重複回避）
  isManual?:       boolean;           // X スライダー手動モード
  manualColdness?: number;            // 手動時のみ使用
  manualRawness?:  number;            // 手動時のみ使用
  previousPattern?: string;           // 前回パターン（構文繰り返し防止）
  count?:          number;            // 3 で3パターン並列生成
  batch?:          boolean;           // true でプレーンJSON返却
}

レスポンス型（GenerateResultData）

interface GenerateResultData {
  raw:          string;   // Claude の生テキスト（===SECTION=== 区切り含む）
  query:        string;   // Tavily に投げたクエリ
  trendSummary: string;   // Tavily 検索結果の要約（3件・各120文字）
  coldness:     number;   // 実際に使った冷徹度
  rawness:      number;   // 実際に使った泥臭さ度
  platform:     string;
}

06 · localStorage仕様

状態はすべてブラウザの localStorage に保持する。 サーバー側に履歴は持たない。SSRでのエラーを防ぐため、 アクセス前に必ず typeof window !== 'undefined' を確認する。

キー一覧

キー型用途

生成完了時のフロー

useGenerate フックが SSE の complete イベントを受け取ったとき、 以下を自動実行する。

function extractPattern(raw: string, platform: 'x' | 'threads'): string {
  const section = platform === 'x' ? 'MEIGEN' : 'OMAMORI';
  const text = extract(raw, section);
  // 最後の句・節を返す（長すぎる場合は後半30文字）
  return text.length > 30 ? text.slice(-30) : text;
}
